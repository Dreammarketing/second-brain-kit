# Етап 0 — Своя копія і перевірка

## Що робимо і навіщо

Цей репозиторій — спільний для групи. Твоя база знань туди не поміщається
і не повинна: там твої клієнти, цифри й домовленості.

Тому перший крок — зробити **свою копію** комплекту у своєму GitHub,
привати, і вже її клонувати на компʼютер. Далі все, що ти створюєш,
живе тільки в твоєму репозиторії.

Заразом перевіримо, що на пристрої є все, що знадобиться далі.

## Що має бути до старту

- Claude Code запускається: набери `claude` у терміналі
- Є акаунт GitHub
- Знаєш свій логін на GitHub

## Як зробити копію

**Варіант 1 — кнопкою, найпростіший.**
Відкрий https://github.com/Dreammarketing/second-brain-kit/generate

- **Repository name** — `my-brain`. Саме так, щоб шляхи в комплекті збігались
- **Visibility** — обовʼязково **Private**

Тиснеш **Create repository** — і в тебе своя повна копія комплекту.

**Варіант 2 — якщо кнопки немає.**
Скажи це Claude у промпті нижче, він зробить копію через `gh` або руками.

Це не форк. Форк тягне за собою звʼязок з оригіналом і публічну історію.
Нам потрібна чиста приватна копія.

Оригінал комплекту: https://github.com/Dreammarketing/second-brain-kit

## Як ти себе поводиш

1. Строго по кроках. Один крок — одне повідомлення. У кінці кожного питай
   «Ідемо далі?» і чекай відповіді. Не перестрибуй, навіть якщо здається швидше.
2. Нічого не робиш мовчки. Спочатку пояснюєш людською мовою, що зараз станеться
   і навіщо, потім робиш.
3. Жодного файлу не видаляєш і не перезаписуєш без мого «так».
4. Без жаргону. Неминучий термін пояснюєш одним рядком.
5. Команда впала — поясни причину простими словами і запропонуй один наступний
   крок. Не перебирай варіанти навмання.
6. У кінці етапу одним рядком: що в мене тепер працює.

## Крок 1. Що вже є на пристрої

Перевір і покажи таблицею «що — версія — годиться чи ні»:

- ОС і версія
- версія Claude Code
- `git` — є, яка версія, чи налаштовані `user.name` і `user.email`
- `gh` (GitHub CLI) — є чи ні, чи авторизований
- `node` — є, яка версія (потрібна 18 або новіша)
- `python3` — є, які версії доступні (потрібна 3.11 або 3.12)
- `docker` — є чи ні, чи запущений
- `brew` — є чи ні (тільки для macOS)
- `jq` — є чи ні

Проти кожного постав: **готово** / **треба поставити** / **треба оновити**.

Нічого поки не став. Просто покажи картину і скажи одним абзацом, що саме
доведеться доставити по дорозі і на якому етапі це знадобиться.

Питай «Ідемо далі?»

## Крок 3. Авторизація в GitHub

Перевір `gh auth status`. Якщо я не авторизований — проведи мене через
`gh auth login`, покроково, пояснюючи кожен вибір у меню.

Вибираємо: GitHub.com → HTTPS → авторизація через браузер.

Коли авторизація пройде — покажи, під яким акаунтом я зайшов.

## Крок 4. Своя приватна копія комплекту

Якщо я вже зробив копію кнопкою **Use this template** — просто спитай назву
репозиторію і переходь до клонування.

Якщо ще не зробив — створи копію сам:

1. Створи приватний репозиторій з моєю назвою через `gh repo create`.
2. Скачай вміст цього комплекту без історії комітів оригіналу.
3. Залий у мій репозиторій першим комітом.

Важливо: копія має бути **приватна**. Перевір це окремо і скажи мені явно,
що репозиторій приватний.

Потім клонуй мій репозиторій у `~/ClaudeCodeProjects/my-brain`. Папку
`~/ClaudeCodeProjects` створи, якщо її немає: це контейнер, у якому далі
житимуть усі мої проєкти поруч із базою. Свого варіанту шляху не пропонуй,
шлях один.

Якщо `my-brain` уже існує і не порожня — нічого не перезаписуй, покажи вміст
і спитай мене.

Питай «Ідемо далі?»

## Крок 5. Захист від витоку

Це найважливіший крок етапу, зроби його уважно.

Створи в корені репозиторію `.gitignore` з таким вмістом:

```
.env
.env.*
!.env.example
*.key
*.pem
.brain/
.DS_Store
node_modules/
.venv/
__pycache__/
raw-export/
```

Поясни мені трьома реченнями, що кожен блок закриває і чому `.env` не можна
класти в Git ніколи.

Створи порожній `.env.example` з коментарем-заглушкою — щоб було видно,
які ключі знадобляться далі, але без самих ключів.

Зроби перший коміт і `push`. Перевір, що на GitHub усе зʼявилось.

Питай «Ідемо далі?»
